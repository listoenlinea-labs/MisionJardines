# Panel de infraestructura

La nueva página Infraestructura aparece debajo de ZKTeco, solo ADMINISTRADOR y SUPER_ADMIN. El inicio no contiene la tarjeta. El backend debe desplegar el commit nuevo: GET /api/infraestructura/estado sin token debe responder 401 (no 404). No publicar tokens. No sustituir variables actuales de ZKTeco.

El botón ZKTeco ejecuta desde Hostinger un diagnóstico inmediato de solo lectura sobre el destino efectivo, usando únicamente la IP dinámica verificada cuando está habilitada, o el destino manual si está deshabilitada. La autolectura se muestra por separado. No se envían comandos de puertas ni escrituras. El botón conmutador encola una orden para la tarea Windows existente; no reinicia servicios activos. Si no hay comunicación reciente se desactiva.

Para ampliar la telemetría instalar la nueva versión de agente.ps1 como recuperar-conmutador.ps1 conservando el respaldo y la tarea existente. Añadir opcionalmente "grandstream": "192.168.1.166" a infraestructura.json; el puerto 80 solo verifica accesibilidad web, no SIP/PSTN. Para obtener systemctl y CLI desde Ubuntu hace falta instalar ubuntu-infra.sh actualizado y la llave SSH restringida siguiendo README.md; sin ella los datos quedan "Sin verificar", nunca activos por suposición. El script Ubuntu envía únicamente estados, contactos configurados y conteos de coincidencias de errores de los últimos 30 mensajes del arranque actual; no transmite journal completo, teléfonos, contraseñas ni audio. No confundir contactos SIP con alcance real. La prueba de llamada y audio sigue siendo física.

Logs del ZKTeco: historial reciente y errores persistentes ya registrados en MySQL, con categorías sin TAG/casa/usuario. Logs del conmutador: eventos de estado y órdenes en memoria más conteos del journal; no historial íntegro persistente. El panel actualiza estado cada 30 s cuando está visible. Las verificaciones del agente dependen de la frecuencia de la tarea. La IP dinámica caduca tras 12 min sin reporte; no se prueba la IP manual automáticamente. Con INFRA_DYNAMIC_ZKTECO=false se puede recuperar manualmente la conexión configurada en Hostinger. El despliegue real y la conexión desatendida aún deben probarse.
